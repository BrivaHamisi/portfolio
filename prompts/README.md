# Implementation Prompts

Before making any nontrivial change to this project, write a short implementation prompt here, get it approved, then implement exactly what it describes. See "How to work" in [AGENTS.md](../AGENTS.md) for the full workflow.

## File naming

One file per change: `YYYY-MM-DD-short-description.md` (e.g. `2026-09-11-add-services-section.md`).

## What a prompt should cover

- **Goal** — what the change is and why.
- **Files touched** — which components/files you expect to add or edit.
- **Approach** — the plan, and any assumptions made.
- **Verification** — manual steps to check it (viewport sizes, `npm run build`, etc.).

Keep prompts short — a few bullets under each heading is usually enough for a site this size.
